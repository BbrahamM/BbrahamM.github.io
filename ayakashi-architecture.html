Decoupling Logic & Presentation

Core Mathematical Model:

  • BtlTurnBaseManager and BtlASkillFormula operate in isolation from Unity transforms, animators, and particles.
  • Hit rates, defense scaling, and damage randomization execute deterministically.

Observer & Event Coordination:

  • beforeApplyAttack: Signals the Cinemachine brain to initiate target framing and screen shake (BtlCameShake).
  • ExecuteAttack: Triggers weapon VFX (BtlShowEffectAtTargget) and audio playback asynchronously.
  • EndApplyEffect: Dispatched by visual scripts once particle playback finishes, allowing the turn scheduler to dequeue the next unit without stalling the framerate.

State Integrity & Synchronization Logic

Atomic Reservation & Turn Revocation:

  • When players stage item commands in battle, units add the item to an ephemeral itemsUsed queue, decrementing the pool immediately.
  • If the player cancels or targets another unit, RevokeAttack() executes RemoveItemUnUse(), returning reserved counts to BtlItemPool via direct dictionary indexing.

Memory Safety & Zero GC Churn:

  • Inventories store quantities mapped to canonical ScriptableObject definitions rather than instantiating runtime GameObject wrappers.
  • Texture and sprite assets are loaded via centralized references, preventing memory leaks during scene transitions.

Hardware-Certified Persistence:

  • Platform-conditional compilation (#if !UNITY_SWITCH) cleanly switches between direct disk I/O and Nintendo Switch native save SDK callbacks.

SOLID Design Principles Applied

  • Single Responsibility Principle (SRP): Combat state sequencing (BtlTurnBaseManager), damage formulas (BtlASkillFormula), item management (BtlItemPool), and persistence (SaveSystemManager) are strictly isolated into single-purpose components.
  • Open/Closed Principle (OCP): Designers create new equipment, skills, and enemy variants purely by adding ScriptableObjects and JSON tables without altering the underlying combat state machine.
  • Liskov Substitution Principle (LSP): BtlWearable inherits transparently from BtlItem. Inventory systems treat all assets as BtlItem polymorphically, while equipment handlers access WearableType safely.
  • Interface & Event Segregation (ISP): Decoupled C# Actions (beforeApplyAttack, afterApplyAttack, toDoWhenWin) ensure UI and VFX managers only observe the exact lifecycle hooks they require.
  • Dependency Inversion Principle (DIP): Combat controllers depend on abstract data classes (CharacterBattleData, ItemPoolData) rather than concrete scene hierarchies.

Production Impact & Designer Velocity

50+ Items Added with Zero C# Modifications:

By shifting item parameters, equipment classification, and localization into ScriptableObjects and JSON data schemas, designers populated the entire dungeon crawler compendium without requesting code adjustments or risk of compilation errors.


Pluggable Skill Formula Strategy Pattern:

Damage and hit-rate routines inherit from BtlASkillFormula. Adding a spell, healing ability, or debuff (e.g. STRDamagePlayer, ApplpyBlindFormula) is as simple as plugging a new formula asset into the skill's inspector slot.


Console Compliance & Robustness:

Decoupled save and UI subsystems ensured rock-solid 60 FPS performance on Nintendo Switch, cleanly passing platform certification criteria.
