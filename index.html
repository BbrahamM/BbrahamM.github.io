Platform Abstraction & Save-Data Integrity

The 257th Element

Shipped Title | Nintendo Switch & PC | Unity, C#, Nintendo SDK, Wwise

The Challenge: One Unity codebase, two platforms. On PC, persistence is simply a file write. On Nintendo Switch, every save, setting, and file-existence check must route through Nintendo's native SDK (nn.fs). If the system sleeps or the player exits the title part-way through a write, the save data is corrupted, causing an immediate failure during console certification.

The Solution: I built a UnityEvent-driven persistence layer with platform-conditional compilation. On Switch, the layer mounts a save-data volume against the preselected player account, then runs every write as an explicit delete → create → open → write → commit transaction. The critical section is guarded by Nintendo SDK exit requests so the OS cannot sleep or close the title mid-write.

The Result: Achieved rock-solid save-data integrity against mid-write power and sleep events. Delivered a single save pipeline serving both SKUs without duplicating game logic, shipping successfully against Nintendo SDK v18.3.2.

// The Critical Section (NintendoManager.cs)

    // OS Exit Guard: Prevents console sleep or quit during transaction
    UnityEngine.Switch.Notification.EnterExitRequestHandlingSection();
#endif

    result = nn.fs.File.Create(filePath, data.Length);
    result.abortUnlessSuccess();

    result = nn.fs.File.Open(ref fileHandle, filePath, nn.fs.OpenFileMode.Write);
    result.abortUnlessSuccess();

    const int offset = 0;
    result = nn.fs.File.Write(fileHandle, offset, data, data.LongLength, nn.fs.WriteOption.Flush);
    result.abortUnlessSuccess();

    nn.fs.File.Close(fileHandle);
    
    // Commit closes the volume transaction as a single unit
    result = nn.fs.FileSystem.Commit(mountName);
    result.abortUnlessSuccess();
